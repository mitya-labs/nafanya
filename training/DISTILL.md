# Teacher distillation spec

This file defines how the teacher model (DeepSeek V4.1 Flash via the API) generates
kuzya tool-selection data. The generator must use the exact 13 tool schemas in
`training/data/tools-schema.json` and the same system prompt as the agent.

## Output format

One JSON object per line:

```json
{"q":"поставь громкость на тридцать","tool":"volume_set","args":{"percent":30},"category":"numbers_in_words","source":"deepseek-v4.1-flash","terms":"DeepSeek Open Platform ToS 2026-04-22 §4.2(3)"}
```

- `tool`: an exact tool name, or `null` when the agent must refuse.
- `args`: only the arguments from the schema; no extra keys.
- `category`: `direct`, `slang`, `typo`, `english`, `indirect`,
  `numbers_in_words`, `near_miss_negative`, `out_of_scope`.
- Do not copy any query from `../kuzya/tests/cases*.json`.
- Do not add explanations, markdown fences or numbering.

## Coverage matrix

| Tool / group | Direct | Slang / typo | Indirect | English / numbers | Total |
|---|---|---|---|---|---|
| `battery_status` | 8 | 4 | 4 | 2 | 18 |
| `wifi_status` | 8 | 4 | 4 | 2 | 18 |

Near-miss negatives are the important ones: stop vs restart, `sshd`/`ssh` services,
Wi-Fi on/off, Bluetooth, "all services", disk/memory, flashlight, timer, calls, files.
They must look like a real request but have no matching tool.

## Teacher prompt

Use the system prompt below and a batch of 20 seeds per call. Replace `{{TOOLS}}`,
`{{SEEDS}}` and `{{BATCH}}`.

```text
You generate training data for a Russian offline phone agent. The agent has exactly
these tools:

{{TOOLS}}

It cannot do anything else. It must answer in text and not call a tool when no tool fits.

Given the seed examples:

{{SEEDS}}

Generate {{BATCH}} new user utterances in Russian with the correct label. Cover the
requested category and vary the wording: slang, typos, mixed English, numbers in words,
indirect requests, and near-miss negatives. Do not reuse the seed wording. Do not copy
any of the frozen test queries. Return strict JSONL, one object per line, with fields
q, tool, args, category. No markdown, no comments.
```

## Generation and validation

1. Generate in batches of 20, with a fixed seed where the API allows it.
2. Append to `training/data/generated/paraphrases-<batch>.jsonl`; never overwrite seeds.
3. Run `python training/scripts/validate_data.py <file>`; fix all errors.
4. Run the leakage check against `../kuzya/tests/cases*.json` before the split.
5. Split by paraphrase family, not randomly; keep a new independent held-out set
   generated by a different model or written by the owner.
