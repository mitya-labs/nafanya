# Data

## JSONL schema

One JSON object per line:

```json
{
  "id": "tp-001",
  "q": "покажи уровень батареи",
  "tool": "battery_status",
  "args": {},
  "category": "direct",
  "split": "train",
  "source": "deepseek-v4.1-flash",
  "terms": "DeepSeek Open Platform ToS 2026-04-22 §4.2(3)"
}
```

- `tool`: exact registered tool name, or `null` for a negative (the assistant must answer
  in text and not call a tool).
- `args`: exact arguments for the tool; `{}` when the tool has no parameters.
- `category`: `direct`, `slang`, `typo`, `english`, `indirect`, `numbers_in_words`,
  `near_miss_negative`, `out_of_scope`.
- `split`: `train`, `dev`, `test` or `heldout`. The independent held-out set must not be
  generated by the same teacher that generated `train`.
- `source`, `terms`: provenance; see `SOURCES.md`.

## Expected files

| File | Description |
|---|---|
| `seeds-teacher-v0.jsonl` | Pilot seed set generated by the teacher, manually reviewed |
| `generated/train.jsonl` | Bulk paraphrases for training (gitignored) |
| `generated/dev.jsonl` | Dev split (gitignored) |
| `generated/test.jsonl` | Internal test split (gitignored) |
| `heldout-v1.jsonl` | Independent held-out set, not used in training |
| `REPORT.md` | Counts per tool, negative share, length distribution, audit notes |
| `SOURCES.md` | Provenance and licence of every data file |

## Validation rules

1. Every `tool` exists in `../kuzya`'s tool registry; every argument matches the JSON
   schema (`tools-schema.json`, generated from `internal/tools`).
2. `mute_set(mode=on)` means mute; `mute_set(mode=off)` means unmute.
3. `nosleep_set(mode=on)` means prevent sleep; `nosleep_set(mode=off)` means allow sleep.
4. `service_restart` and `service_logs` only use the seven allowed units.
5. No duplicate and no near-duplicate against `../kuzya/tests/cases*.json` (token-set
   Jaccard ≥ 0.7 or edit distance ≤ 0.2 fails the build).
6. Negatives are 35–40% of the final dataset and include both out-of-scope and near-miss
   requests.
